# ServerMMO — плагины для Paper 26.3

Кастомная система здоровья, урона, уровней и HUD. Четыре связанных плагина плюс
ресурспак. Всё уже собрано и лежит в [`server/plugins/`](../server/plugins/), так что
для игры ничего компилировать не нужно.

---

## Что делают плагины

| Плагин | Jar | За что отвечает |
|---|---|---|
| **ServerMMOCore** | `servermmo-core-1.0.0.jar` | Таблица 90 уровней, кастомное здоровье и урон на `long`, профили игроков, ванильные статы отключены |
| **ServerMMOMobs** | `servermmo-mobs-1.0.0.jar` | Мобы замечают игрока в радиусе 20 блоков, поворачивают голову и тело, бьют по кастомной системе |
| **ServerMMOPlayers** | `servermmo-players-1.0.0.jar` | Опыт за убийство мобов, повышение уровня, команда `/stats` |
| **ServerMMOHud** | `servermmo-hud-1.0.0.jar` | Рамка в левом верхнем углу: здоровье, урон, уровень, опыт |

Зависимости простые: `mobs`, `players` и `hud` не включатся без `core`.
Paper сам выстроит порядок загрузки по `depend:` в `plugin.yml`.

## Как это работает

### Здоровье и урон

* У каждого игрока и моба есть **своё** здоровье, которое хранится в `long`
  (до 9 223 372 036 854 775 807). Ванильные `MAX_HEALTH`, `ATTACK_DAMAGE`,
  `ARMOR` обнуляются, чтобы не мешать.
* Любой ванильный урон отменяется и пересчитывается заново:
  * игрок бьёт моба — урон берётся из статов игрока (`player-stats.yml`);
  * моб бьёт игрока — урон берётся из таблицы мобов (`stats.yml`);
  * падение, лава, кактус, взрыв — ванильное значение ×
    `combat.environment-damage-scale` (по умолчанию 1:1).
* Удар вызывает ванильное покраснение и звук (`playHurtAnimation`).
* Когда кастомное здоровье кончается:
  * **моб** — проигрывается звук смерти, сущность исчезает. Анимации смерти и
    дропа нет вообще;
  * **игрок** — обычная ванильная смерть и респавн с полным здоровьем.

### Уровни и опыт

* Игрок начинает с **10 HP / 1 урон / 1 уровень / 0 из 200 опыта**.
* За убийство моба даётся опыт из столбца «Опыт» таблицы.
* Когда опыт переполняет столбец «До след. уровня», игрок получает следующий
  уровень, полностью лечится и получает статы нового уровня.
* Со 2 уровня статы игрока совпадают с мобом того же уровня из таблицы.

### Мобы

* **Обычные мобы в мире — полностью ванильные**: их здоровье, урон, AI, дроп и
  смерть не трогаются, кастомная система их не замечает.
* **Кастомные мобы появляются только командой** (в будущем — точками из
  конфига):

  ```
  /mob spawn <уровень> <тип> [x y z]
  /mob spawn 2 Курица
  /mob spawn 40 zombie 100 65 -20
  ```

  Тип можно указать по-русски (как в таблице) или по имени игры (`chicken`,
  `zombie`). Без координат моб появляется на месте игрока.
* Автоматический спавн по координатам — секция `spawns` в
  `plugins/ServerMMOMobs/config.yml`; мобы появляются при старте сервера:

  ```yaml
  spawns:
    - world: world
      type: Курица
      level: 2
      x: 100
      y: 65
      z: -20
  ```
* Кастомному мобу выдаются статы строки таблицы: здоровье, урон, опыт, а также
  уровень. Уровень важнее типа: курица 40 уровня сильнее курицы 2 уровня.
* Кастомные мобы замечают игрока в радиусе **20 блоков**: враждебные получают
  цель и идут в атаку ванильным AI, мирные и нейтральные идут через
  `Pathfinder` и бьют вручную, когда подошли. Все разворачивают тело
  (`setRotation`) и голову (`lookAt`) в сторону игрока.
* Над кастомным мобом висит подпись **`LVL 2 Курица 11`**: слева значок
  уровня, сразу за ним номер уровня, потом имя моба ванильным шрифтом и
  здоровье. Значок `LVL` и числа — глифы ресурспака; они нарисованы в тех же
  строках ячейки, что ванильные заглавные буквы (7 px, строки 1..7), поэтому
  значок, цифры и имя стоят на одной базовой линии и подпись не «пляшет».
  Слова «Ур» и сердца в подписи нет. Без пака значка не будет, числа
  отрисуются ванильным шрифтом — подпись останется читаемой.
* Перебираются только кастомные мобы: они берутся под наблюдение при спавне
  и при загрузке чанка, полный скан мира не делается.
* Кастомный моб умирает без анимации смерти и без дропа, только со звуком.

### HUD

* Четыре строки в левом верхнем углу: **сердце + здоровье**, **меч + базовый
  урон**, **LVL + уровень**, **XP + `опыт/до следующего`**.
* Иконки, буквы LVL/XP и цифры — картинки из ресурспака (`servermmo:hud`), а не
  ванильный шрифт. Ячейка глифа 8x8, как у ванильного шрифта, а чернила
  занимают строки 1..7 — ровно как заглавные буквы и цифры ванильного
  `ascii.png`, поэтому строка не «прыгает» и иконки не вылезают над текстом.
* Панель висит перед камерой (`TextDisplay` с billboard `CENTER`), поэтому она
  всегда развёрнута к игроку и видна в левом верхнем углу кадра. Фон у
  таблички отключён (`setDefaultBackground(false)`) — тёмных плашек за текстом
  нет, а яркость выставлена максимальной, чтобы HUD не темнел ночью.
* Все 47 ванильных спрайтов сердец (обычные, тёмные, замороженные, хардкорные,
  «мигающие», при езде на мобе) заменены прозрачными PNG, старый `icons.png`
  тоже. Полоса опыта, броня и голод скрыты так же.
* Значения живые: здоровье, урон, уровень и опыт.
* Если пак не установлен, вместо иконок будут пустые квадратики. Вид
  подстраивается командой `/hud scale|distance|offsetx|offsety`.

## Установка

1. Скопируй `server/` на Windows-машину (или возьми готовый zip-пак).
2. Убедись, что в `server/plugins/` лежат четыре jar-файла `servermmo-*.jar`.
3. Запусти `start.bat`. В логе должно появиться:

   ```
   [ServerMMOCore] ServerMMOCore включён: уровней 90, статов игрока 90
   [ServerMMOMobs] ServerMMOMobs включён: кастомные мобы только по команде /mob spawn, радиус агро 20.0 блоков
   [ServerMMOPlayers] ServerMMOPlayers включён
   [ServerMMOHud] ServerMMOHud включён
   ```

4. Установи ресурспак (см. ниже) — без него вместо рамки будут пустые квадраты.

### Ресурспак

Файл: [`server/resourcepack/servermmo-hud.zip`](../server/resourcepack/servermmo-hud.zip)
(26488 байт, SHA-1 `1ae261416f0ac24d925725bdafdca176dca57dfe`).

**Вариант 1 — сервер раздаёт сам (по умолчанию):**

Плагин `ServerMMOCore` поднимает HTTP-раздачу внутри процесса Paper, так что
отдельное окно не нужно. Клиент получает ссылку и качает zip сам.

1. `server/setup-resourcepack.bat` — спрашивает URL (Enter = предложенный
   `http://<lan-ip>:8080/servermmo-hud.zip`), считает SHA-1 и пишет в
   `server.properties`: `resource-pack`, `resource-pack-sha1`,
   `resource-pack-prompt`, `require-resource-pack`
   (старый файл → `server.properties.bak`).
2. Запустить `start.bat`. В консоли будет блок «Раздача ресурспака» с файлом,
   SHA-1 и адресами; плагин сверит `server.properties` с реальным файлом и
   предупредит, если строка протухла.
3. Игроки получают предложение скачать пак при входе.

Настройки — `plugins/ServerMMOCore/config.yml`, раздел `resourcepack`:

```yaml
resourcepack:
  serve: true                                   # false — не открывать порт
  port: 8080                                    # тот же, что PACK_PORT в settings.bat
  file: resourcepack/servermmo-hud.zip
  bind: 0.0.0.0
  public-url: ""                                # внешний адрес, если сервер за NAT/прокси
```

Через интернет нужен проброс порта `8080` (как `25565` для Minecraft) либо
внешний адрес в `public-url` (туннель, reverse proxy).

**Вариант 1b — отдельный мини-сервер:** `server/pack-server.bat` делает то же
самое, но отдельным процессом; нужен только для раздачи при выключенном
Minecraft-сервере (порт тот же, одновременно не запустить).

**Вариант 2 — публичный хостинг:**

Залей zip туда, где есть прямая ссылка (GitHub Pages в публичном репозитории,
Cloudflare R2, любой статический хостинг) и выполни:

```bat
setup-resourcepack.bat https://example.com/servermmo-hud.zip
```

Ссылка с GitHub Release в приватном репозитории не подойдёт: клиент Minecraft
не умеет авторизовываться в GitHub.

**Вариант 3 — вручную каждому игроку:**

1. Скопируй `servermmo-hud.zip` в `.minecraft/resourcepacks`
   (`%APPDATA%\.minecraft\resourcepacks`).
2. В игре: **Настройки → Наборы ресурсов** → включить «ServerMMO HUD».

Посчитать SHA-1 вручную (если правишь `server.properties` без скрипта):
`Get-FileHash servermmo-hud.zip -Algorithm SHA1` в PowerShell или
`sha1sum servermmo-hud.zip` в Linux/macOS.

`require-resource-pack=true` заставляет принять пак (отказ = кик).
По умолчанию `false`: игрок без пака зайдёт, но увидит пустые квадраты.

> Если ресурспак не установлен, HUD покажет пустые квадраты вместо рамки и
> цифр. Проверка: открой URL из `server.properties` в браузере на другом
> устройстве — должен скачаться zip.

## Команды

| Команда | Право | Что делает |
|---|---|---|
| `/stats` | всем | свои уровень, здоровье, урон и опыт |
| `/stats <ник>` | всем | статы другого игрока |
| `/stats reset [ник]` | оператор | сброс к 1 уровню |
| `/hud scale 0.30` | оператор | размер рамки |
| `/hud distance 1.0` | оператор | расстояние до плоскости HUD |
| `/hud offsetx -0.92` | оператор | сдвиг влево/вправо |
| `/hud offsety 0.60` | оператор | сдвиг вверх/вниз |
| `/hud reset` | оператор | вернуть заводские значения |

`/hud` пишет значение в `plugins/ServerMMOHud/config.yml` и сразу применяет его.
Если рамка «улетела» за экран или слишком крупная — подстрой эти четыре числа
под своё разрешение и FOV.

## Настройки

### `plugins/ServerMMOCore/config.yml`

```yaml
debug: false

combat:
  environment-damage-scale: 1.0   # ванильный урон падения/лавы -> кастомный
  strip-vanilla-stats: true       # обнулять MAX_HEALTH, ATTACK_DAMAGE, ARMOR
  mob-death-sound: true           # звук смерти моба
  mob-death-animation: false      # анимация смерти (по ТЗ выключена)
  hurt-animation: true            # покраснение при ударе

storage:
  save-interval-seconds: 300      # автосохранение профилей
```

### `plugins/ServerMMOMobs/config.yml`

```yaml
aggression:
  radius: 20.0                 # радиус агро в блоках
  look-at-target: true         # поворот головы и тела
  peaceful-mobs-attack: true   # мирные тоже атакуют
  attack-cooldown-ticks: 20    # пауза между ударами (20 тиков = 1 сек)
  attack-reach: 2.6            # дальность удара
  follow-speed: 1.0            # скорость преследования
  check-interval-ticks: 10     # частота проверки
```

### `plugins/ServerMMOHud/config.yml`

```yaml
hud:
  distance: 1.0        # расстояние до плоскости HUD
  offset-x: -0.92      # влево от центра
  offset-y: 0.60       # вверх
  scale: 0.30          # размер
  update-interval-ticks: 1
  see-through: true    # рисовать поверх блоков

resource-pack:
  enabled: false       # автораздача пака (нужен url)
  url: ""
```

## Таблицы статов

### `plugins/ServerMMOCore/stats.yml`

90 уровней: `mob`, `type` (EntityType Paper), `health`, `damage`, `xp`,
`xp-to-next`. Пример:

```yaml
levels:
  1:
    mob: "Лосось"
    type: SALMON
    health: 3
    damage: 1
    xp: 4
    xp-to-next: 12
```

Файл можно править руками — плагин читает его при запуске. Если правишь
`tools/mobs_stats.txt` (исходную таблицу), перегенерируй:

```bash
python3 tools/gen_stats.py
```

### `plugins/ServerMMOCore/player-stats.yml`

То же для игрока. 1 уровень задан по макету HUD (20/5/200), дальше — как у мобов.
Правь свободно: `health`, `damage`, `xp-to-next`.

## Сборка из исходников

Исходники: [`plugins/`](.) — Maven-мультимодуль, Java 25, Paper API
`26.3.build.151-beta`.

```bash
mvn -f plugins/pom.xml clean package
```

Готовые jar появятся в `plugins/*/target/`. Скопируй их в `server/plugins/`.

Автоматическая сборка уже настроена в GitHub Actions
([`.github/workflows/build-plugins.yml`](../.github/workflows/build-plugins.yml)):
при каждом push, который меняет `plugins/`, Maven собирает все четыре jar и
коммитит их в `server/plugins/`. Если сборка падает — лог коммитится как
`build.log`.

### Проверка артефактов

```bash
python3 tools/check_plugins.py
```

Проверяет `plugin.yml` внутри jar, главные классы, api-version `26.3`, таблицы
90 уровней, формат ресурспака `97.1` и наличие всех глифов.

### Ресурспак из исходников

```bash
python3 tools/gen_resourcepack.py
```

Перерисовывает рамку, иконки и шрифт, собирает
`server/resourcepack/servermmo-hud.zip`.

## Порядок загрузки и совместимость

* Paper 26.3, Java 25.
* Плагины используют `plugin.yml` (не `paper-plugin.yml`) и `depend`, поэтому
  видят классы ядра напрямую.
* Если поставить только `servermmo-mobs.jar` без ядра, он выключится с записью
  `ServerMMOCore не загружен - выключаюсь`.
* Другие плагины (EssentialsX, WorldGuard и т.п.) работают как обычно, но их
  собственный урон тоже проходит через кастомную систему.
