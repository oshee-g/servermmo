# Тесты и проверки (папка `tools/`)

Это служебная папка для проверки скриптов пака. Пользователю, который просто
поднимает сервер, она не нужна — но если ты правишь `start.bat` или `start.sh`,
прогони эти тесты, чтобы убедиться, что ничего не сломалось.

## Быстрый прогон

```bash
cd <корень репозитория>
python3 tools/check_plugins.py      # собранные jar, таблицы статов, ресурспак
python3 tools/lint-bats.py          # статические проверки .bat
python3 tools/test-bats.py          # поведение .bat (Windows-логика)
bash   tools/test-linux.sh          # поведение .sh (Linux/macOS)
```

## Генераторы статов и ресурспака

### `gen_stats.py` — таблицы статов из `mobs_stats.txt`

Читает `tools/mobs_stats.txt` (таблица 90 уровней) и пишет:

* `plugins/servermmo-core/src/main/resources/stats.yml` — статы мобов по уровням;
* `plugins/servermmo-core/src/main/resources/player-stats.yml` — статы игрока.

Русские названия мобов переводятся в `EntityType` Paper 26.3 (например,
`Лосось` → `SALMON`, `Хранитель` → `WARDEN`). 1 уровень игрока переопределён
по макету HUD: 10 HP / 1 урон / 200 опыта до следующего уровня.

Все числа пишутся как целые `long`.

### `gen_resourcepack.py` — сборка HUD-пака

Берёт готовые PNG из `tools/pack_assets/`, пишет шрифт
`assets/servermmo/font/hud.json`, прозрачные заглушки ванильных сердец и
полос, упаковывает всё в `server/resourcepack/servermmo-hud.zip`.

`pack.mcmeta` пишется под Minecraft 26.3: формат ресурспака **97.1**
(`min_format: [97, 1]`, `max_format: 97`).

### Текстуры HUD

* `tools/assets_src/` (в git не хранится) — крупные картинки от генератора
  изображений: панель, сердце, меч, щит, кристалл (фон — чистый зелёный).
* `tools/build_hud_assets.py` — вырезает фон, уменьшает до пиксель-арта и
  собирает `tools/pack_assets/` (результат коммитится): иконки 8x8, атласы
  цифр и иконок, `pack.png`, `hud-preview.png`. Нужен Pillow, запускается
  вручную, в CI не нужен.
* `tools/gen_resourcepack.py` — без сторонних библиотек: раскладывает PNG по
  структуре ресурспака, пишет `hud.json`, прячет ванильные сердца и собирает
  zip с фиксированными таймстампами.
* `tools/check_pack.py` — проверяет готовый zip: шрифт на месте, все
  bitmap-провайдеры 8x8, 47 спрайтов сердец прозрачные.

Важно: в шрифте Minecraft ячейка глифа квадратная (`height`x`height`), а
ширина символа считается по правому непрозрачному пикселю + 1. Поэтому одна
длинная полоса (160x14) символом быть не может — клиент брал из неё только
первые 14 пикселей, и HUD не отображался.

### Раздача ресурспака

По умолчанию пак отдаёт сам Paper — HTTP-сервер живёт
внутри `ServerMMOCore` (`core/src/main/java/ru/servermmo/core/web/ResourcePackServer.java`,
настраивается в `config.yml`, раздел `resourcepack`). Smoke-тест поднимает
настоящий сервер и проверяет `/health`, `/sha1`, `/`, скачивание zip со сверкой
SHA-1, 404 на неизвестный путь и 405 на POST.

`server/pack-server.bat` + `server/resourcepack/PackServer.java` — тот же
протокол отдельным процессом, на случай раздачи при выключенном Minecraft.

`server/setup-resourcepack.bat` вызывает
`server/resourcepack/SetupPack.java`: тот считает SHA-1 и правит
`server.properties` (читается как ISO-8859-1, поэтому остальной файл
сохраняется байт в байт; делается бэкап `server.properties.bak`).
Оба файла запускаются в режиме `java File.java` — компилятор не нужен,
но нужен именно JDK (модуль `jdk.compiler`), а не голый JRE.

Проверяется автоматически в `.github/workflows/smoke-test.yml` на JDK 25:

* `PackServer.java` — скачивается zip, сверяется SHA-1, проверяются
  `Content-Length`, 404 на неизвестный путь, 405 на POST, индексная страница;
  лог складывается в `packserver-test.log`;
* `SetupPack.java` — правится копия `server.properties`: проверяются
  `resource-pack`, `resource-pack-sha1`, `require-resource-pack`, промпт,
  отсутствие дублей, сохранение не-ASCII байтов и создание `.bak`.

### `check_plugins.py` — проверка артефактов

* `plugin.yml` внутри каждого jar: `name`, `main`, `api-version: '26.3'`;
* наличие главного класса и пакета `ru/servermmo/`;
* `stats.yml` и `player-stats.yml`: 90 уровней, значения в пределах `long`,
  первый уровень игрока = 20/5/200;
* ресурспак: формат 97.1, все текстуры шрифта на месте, все глифы и сдвиги
  (`\uE001`…`\uE006`, `\uE100`, цифры) объявлены; `pack.mcmeta` в корне zip;
* `server.properties`: если `resource-pack` заполнен, `resource-pack-sha1`
  обязан совпадать с реальным SHA-1 файла ресурспака.

Запускать после `mvn package` или после того, как CI опубликовал jar в
`server/plugins/`.

## Что внутри

### `lint-bats.py` — статический анализ `.bat`

Ищет типичные ошибки батников:

* `goto`/`call` на несуществующую метку и повторяющиеся метки;
* переменные `%ИМЯ%`, которые нигде не заданы (сверяется с `settings.bat`);
* непарные кавычки в строке;
* комментарии `::` внутри блока `( ... )` — в `cmd.exe` это ломает блок;
* неэкранированные `(`, `)`, `|`, `&`, `<`, `>` внутри `echo` в блоке;
* не-ASCII байты (на Windows другая кодировка → «кракозябры»);
* смешанные переводы строк.

### `test-bats.py` — прогон `.bat` без Windows

В песочнице нет `cmd.exe`, поэтому в файле живёт маленький интерпретатор
подмножества batch, которое используют наши скрипты (`goto`, `call`, `if exist`,
`if "%a%"=="%b%"`, `if errorlevel`, `set`, `echo` с перенаправлением,
блоки `( ) > файл`, `exit /b`, `choice`, `findstr`, `where`, `pause`, `timeout`).
Моки подменяют `powershell`, `java`, `choice` и сеть, поэтому можно проверить
все ветки: нет интернета, нет Java, старая Java, `eula=false`, уже
установленное ядро, отказ от перезапуска, `AUTO_RESTART=yes` и т. д.

Сценарии печатают `[PASS]`/`[FAIL]`; в конце — итог. Возвращает код 1, если
что-то упало.

> Ограничение: это модель `cmd.exe`, а не он сам. Основные конструкции она
> проверяет, но 100 % гарантии синтаксиса реального `cmd` не даёт.

### `test-linux.sh` — прогон `.sh`

Создаёт временную копию `linux/`, подкладывает в `PATH` подставные `curl`
(отдаёт JSON, как у PaperMC API, и фейковый `paper.jar` с правильной SHA-256)
и `java` (с настраиваемой версией). Проверяет:

* скачивание ядра и проверку SHA-256 (включая случай битой загрузки);
* отсутствие сети и подсказку про ручное скачивание;
* проверку Java (нет Java / Java 21 / Java 25);
* `eula.txt` (создание и `eula=false`);
* повторный запуск без обращения к сети;
* `update.sh` (новое ядро + сохранённый `paper.jar.old`);
* `backup.sh` (архив содержит мир, Nether, плагины; «нечего бэкапить» → код 1).

## Если правишь скрипты

1. Меняй файлы в `server/` (Windows) и `linux/` (bash) — они независимы.
2. Прогони три команды выше.
3. Не добавляй в `.bat` русский текст: на Windows кодировка консоли не UTF-8,
   сообщения превратятся в мусор. Русский язык — в `README.md`.
